# Codex 身份 v2 试验

这项功能在现有账号隔离和指纹收敛之上，保持 session、thread、窗口与父子引用的关系，并让 HTTP、兼容桥与原生 WebSocket 使用相同的身份处理流程。参考实现固定为 KlN-4096/sub2api 的 `295f9f39562de2280523f5aada0bbea21836b330`，按本项目接口选择性适配。

账号的 **Codex 身份版本** 默认是 **v1（兼容）**。升级不会给存量账号自动开启 v2。创建、编辑、批量编辑 OpenAI OAuth/setup-token 账号时可选择 **v2（试验）**；影子账号继承凭证来源账号的版本，需编辑母账号。现有指纹模式和随机 seed 保留。

建议先选择少量账号，从新会话开始试用 `v2 + 仅设备`。设备收敛不会把不同线程合并。`session/full` 仍是显式选择的会话/线程合并策略，应确认需要后再启用；`off` 只关闭收敛，账号隔离继续生效。

管理 API 对应字段在 `extra` 中：

```json
{
  "codex_identity_version": "v2",
  "codex_fingerprint_mode": "device"
}
```

版本仅接受字符串 `v1` 或 `v2`。更新时省略版本表示保留原值，回退需显式设置 `v1`。不需要新增数据库表，也不需要重新生成账号 seed。

本次包含：

- 当前 WS 帧的 turn metadata 优先，握手值仅在字段缺失时回填。这项协议修复也适用于 v1。
- v2 的身份派生保留复合窗口编号、默认缓存关系、父子引用和 UUIDv7 时间戳；HTTP、透传、Chat/Messages 桥、原生 WS 首帧及后续帧共用处理。
- WS 池按代理、URL、UA、凭证域、版本和账号指纹配置区分连接，配置变化后新请求不复用旧配置连接；预热使用配置快照。
- v2 turn-state 按 blob 摘要、凭证域及版本判断归属，仅在实际响应提交后记录。未知来源保持透传，已知异凭据/版本来源剥离。v1 沿用旧规则，额外剥离已知 v2 blob。
- 上游会话状态按版本及指纹配置隔离；应用内调度和执行作用域仍取原始客户端标识。

本轮未引入基于 blob 长度的模型质量推断、手工 turn-state 覆写、自动接管、时区/搜索位置改写、额外账号 GET、CPR 或图片路由变更。传输压缩和配额重构另行评估。

回退分两层：

1. 配置回退：将母凭证账号版本设为 `v1`，保留原 seed，并从新会话开始。连接兼容键会隔离新旧配置；已经在途的连接按启动时配置完成，切换设置不能撤回已发出的请求。
2. 代码回退：使用移植前固定提交构建的镜像或切回保留的原分支。配套 `ROLLBACK.sh` 只用于显式指定的源码副本，并校验文件状态后恢复原始字节，不会回滚线上数据库或代替容器部署。

验证应使用本地模拟上游，同时检查旧身份固定样本、真实 HTTP/WS 发送内容、多轮窗口、失败换号、版本切换、图片权限与计费。离线通过不能证明实际配额或模型质量提升。

turn-state v2 来源缓存是**单进程**内存缓存：上限 16,384 条，TTL 沿用 WS session sticky TTL。跨实例、重启、过期和容量淘汰后的来源未知，继续透传；这不构成集群级状态归属保证。多实例部署应先加入共享来源存储或确认粘性，再扩大试用。
