# Codex 身份 v2 试验

这项功能在现有账号隔离和指纹收敛之上，保持 session、thread、窗口与父子引用的关系，并让 HTTP、兼容桥与原生 WebSocket 使用相同的身份处理流程。参考实现固定为 KlN-4096/sub2api 的 `295f9f39562de2280523f5aada0bbea21836b330`，按本项目接口选择性适配。

账号的 **Codex 身份版本** 默认是 **v1（兼容）**。升级不会给存量账号自动开启 v2。创建、编辑、批量编辑 OpenAI OAuth/setup-token 账号时可选择 **v2（试验）**；影子账号继承凭证来源账号的版本，需编辑母账号。现有指纹模式和随机 seed 保留。

建议先选择少量账号，从新会话开始试用 `v2 + 仅设备`。设备收敛不会把不同线程合并。`session/full` 仍是显式选择的会话/线程合并策略，应确认需要后再启用；`off` 只关闭收敛，账号隔离继续生效。

管理 API 对应字段在 `extra` 中：

```json
{
  "codex_identity_version": "v2",
  "codex_fingerprint_mode": "device"
}
```

版本仅接受字符串 `v1` 或 `v2`。更新时省略版本表示保留原值，回退需显式设置 `v1`。不需要新增数据库表，也不需要重新生成账号 seed。

本次包含：

- 当前 WS 帧的 turn metadata 优先，握手值仅在字段缺失时回填。这项协议修复也适用于 v1。
- v2 的身份派生保留复合窗口编号、默认缓存关系、父子引用和 UUIDv7 时间戳；HTTP、透传、Chat/Messages 桥、原生 WS 首帧及后续帧共用处理。
- WS 池按代理、URL、UA、凭证域、版本和账号指纹配置区分连接，配置变化后新请求不复用旧配置连接；预热使用配置快照。
- v2 turn-state 按 blob 摘要、凭证域及版本判断归属，仅在实际响应提交后记录。未知来源保持透传，已知异凭据/版本来源剥离。v1 沿用旧规则，额外剥离已知 v2 blob。
- 上游会话状态按版本及指纹配置隔离；应用内调度和执行作用域仍取原始客户端标识。

Team turn-state 改进增加了默认关闭的 HTTP 状态观测、候选采集和缺头复用，见下节。仍不根据 blob 长度判断模型质量，不提供手工 turn-state 覆写，不自动切换出口或主动探测账号。

## Team 状态观测与候选复用

账号创建、编辑、批量编辑中的 Codex 身份 v2 下增加 **Turn-state 模式**：

- **关闭**：默认；保留原有透传/来源守卫。
- **仅观测**：从已提交给客户端的原生 HTTP `/responses` 响应采集长度与来源，符合候选条件时保存在本进程内。不会补写出站状态。
- **复用候选**：在上一步基础上，仅当原生 HTTP 请求没有客户端状态、没有 `previous_response_id` 时，尝试使用同一凭据、身份配置和上游模型的候选。

候选长度默认 `292, 332`，可以为你的 Team 账号设为 `332`；空列表只观测，不选择候选。每种长度都是待验证的协议观测，**292/312/332 都不是 HTTP 状态码，也不能单独证明正常或降级**。不会按照账号的套餐标签猜测长度；Team workspace 权益与个人套餐字段并不总是同一个信息。

```json
{
  "codex_identity_version": "v2",
  "codex_turn_state_mode": "observe",
  "codex_turn_state_candidate_lengths": [332]
}
```

这些字段放在账号 `extra` 下，模式只接受 `off/observe/reuse`；长度数组最多 8 个不同整数，每项 100–2048。省略字段保留原配置。母凭据控制影子账号的模式，实际身份配置仍独立隔离。切回 v1 后观测/复用不生效。

编辑账号时的观测面板按实际上游模型显示长度分布、候选摘要、签发时间、本地截止时间和复用尝试次数，并可刷新/清空。管理员 API 为 `GET/DELETE /api/v1/admin/accounts/:id/codex-turn-state`；它们继承现有管理员鉴权，不返回状态原文、token 或代理密码。清空作用于当前进程、当前账号身份配置中的所有模型。

候选必须来自有归属的真实响应提交点；失败换号、首输出前失败和已经提交的旧响应头不会进入候选库。输入长度需在配置列表，Fernet 外层需结构完整、Base64URL 规范、签发时间不在未来，并在本地一小时上限内。没有上游密钥，因此这仅是结构检查，不是签名验证；一小时是本地保留策略，不承诺服务器接受时长。重复观察或复用不会延长原期限。

缓存最多 1024 个凭据/模型桶，每桶最多 16 种长度统计及一个候选，原文仅保存在内存。其他长度计入汇总，不覆盖候选。新请求会重新检查当前长度列表；被上游 4xx 拒绝的候选停用（429 除外），不额外发请求重试，不影响已有错误处理。复用尝试次数不能当成上游接受次数。

Team workspace 不等于成员身份：v2 溯源在缺少 `chatgpt_user_id` 时额外按本地凭据记录及 bearer 摘要区分，避免两个未知成员仅因 workspace 相同就被视为同一来源。具备可靠 user ID 的已知同主体来源继续兼容。候选库还按凭据记录、模型、身份版本、指纹模式/seed/device、自定义 UA 和代理配置隔离。

这次候选观测/复用只覆盖原生 HTTP `/responses`，普通转发和透传均包含；**原生 WS、`/responses/compact`、Chat/Messages 兼容桥继续使用既有续接逻辑**。客户端已经携带的状态具有优先级，已知异凭据状态仍由来源守卫剥离。不会覆盖它再强塞候选。进程重启清空候选，多实例各自观测，管理请求只能看到命中的实例。

建议先给一个 Team 账号开启“仅观测”，在真实 HTTP 流量中确认长度与模型；再按需开启“复用候选”，分别验证上游接受率、长会话、错误率和回答质量。关闭模式即可停止新请求的采集和复用；已在途请求按发送时配置完成。

回退分两层：

1. 配置回退：将母凭证账号版本设为 `v1`，保留原 seed，并从新会话开始。连接兼容键会隔离新旧配置；已经在途的连接按启动时配置完成，切换设置不能撤回已发出的请求。
2. 代码回退：使用移植前固定提交构建的镜像或切回保留的原分支。配套 `ROLLBACK.sh` 只用于显式指定的源码副本，并校验文件状态后恢复原始字节，不会回滚线上数据库或代替容器部署。

验证应使用本地模拟上游，同时检查旧身份固定样本、真实 HTTP/WS 发送内容、多轮窗口、失败换号、版本切换、图片权限与计费。离线通过不能证明实际配额或模型质量提升。

turn-state v2 来源缓存是**单进程**内存缓存：上限 16,384 条，TTL 沿用 WS session sticky TTL。跨实例、重启、过期和容量淘汰后的来源未知，继续透传；这不构成集群级状态归属保证。多实例部署应先加入共享来源存储或确认粘性，再扩大试用。
