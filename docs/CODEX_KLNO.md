# klno Codex 方案

本分支完整采用 KlN-4096/sub2api 的 klno 分支中 Codex 指纹收敛、Turn-State 自动接管、猎手和恢复探测方案。参考提交：`3ad8dc0cca47998e533449ec29b5809ca146dae9`。

账号列表的用量下方显示状态形态（例如 332）、模型、剩余有效期比例、剩余分钟及猎手摘要。百分比是本地候选有效期的剩余比例，不是模型质量或命中率。

配置位于账号编辑窗口：设备指纹模式配合实验性指纹收敛控制线协议投影；自动接管控制候选池及 HTTP 注入；猎手配置模型、代理、动态出口和时间预算；恢复探测独立配置。猎手所选代理用于探测，正常请求保持账号自己的代理绑定。

上游按模型维护数据库候选池，默认每模型三张候选，识别 292 和 Team 332 两种形态。HTTP 采用上游按会话判断及猎手模型优先接管策略；WebSocket 保留上游手填与客户端续接策略。状态形态只是一项启发式判断，不能证明上游实际提供某个模型。

采用上游探针语义：收到状态头后结束读取，按形态接收候选；配置记账 Key 后，探测输入用量按本地估算记账，输出记零。管理员用量可区分新铸状态、实际发送状态以及手填／自动来源。

旧 v2 选择器和单候选缓存链路已移除。迁移会将原 v2 的指纹开关映射至 `codex_experimental_fingerprint_convergence`，将原 `reuse` 映射至 `openai_turn_state_auto`，已显式配置的上游开关优先。旧设置键保留为停用元数据，供旧镜像回退读取，正常代理绑定不会迁移。

保留原项目的其他功能与修复；本次不引入上游的 CPR 账号类型等独立功能。数据库采用追加迁移，保留已发布的 239 迁移文件校验和。

回退基线：分支 `codex/improve-v2-team-turn-state`，提交 `71fc7b4c33093734cd7a38079ab01ce0fc772e45`，镜像 `ghcr.io/masatoshiyokoyama635-sudo/sub2api:codex-identity-v2-team-71fc7b4`。新镜像使用独立 `codex-klno` 标签。
